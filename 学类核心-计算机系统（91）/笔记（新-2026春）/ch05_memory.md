## 5.1 计算机的存储

### 5.1.1 计算机的存储和寻址体系

#### 什么是"行"

“行”（Line）是**数据传输的最小单位**，也是缓存中**实际存储数据的基本容器**。它的标准全称是**缓存行（Cache Line）**。

一个缓存行一般由三部分组成:

1. **有效位(valid bit)**
2. **标记位(Tag)**
3. **数据块(Data)**

> 我们说“缓存行大小为 64 字节”，指的就是这个 **数据块（Data Block）** 的大小，而不是整个行的总大小（加上Tag和Valid位会略大一些）。

#### "页"和"行"的区别

| 对比维度     | **页（Page）**                                   | **行（Cache Line）**                            |
| :----------- | :----------------------------------------------- | :---------------------------------------------- |
| **所属层级** | **虚拟内存/物理内存**（主存 DRAM 层）            | **CPU 缓存（Cache）**（SRAM 层）                |
| **管理者**   | **操作系统（OS）+ MMU（内存管理单元）**          | **CPU 硬件（Cache 控制器）**                    |
| **核心作用** | 解决“进程虚拟地址”与“物理内存地址”的**映射**问题 | 解决 CPU 与物理内存之间**速度不匹配**的加速问题 |
| **典型大小** | **4KB**（也有 2MB/1GB 的大页，但基础是 4KB）     | **64 字节**（现代 Intel/ARM 标准）              |

**他们在数据传输中的分工**

1. 缺页异常时 -- 按"页"搬运

   当程序访问的内存不在物理内存中（缺页）时，操作系统会去**硬盘（磁盘/Swap分区）**，把包含该地址的**整整 4KB（一个页）**的数据，整体搬运到物理内存中。**注意**：硬盘太慢，按“行”（64B）搬会频繁死机，所以必须一次多搬点，按“页”来。

2. CPU 读数据时 -- 按"行"安装

   数据从硬盘搬到物理内存后，CPU 发出读指令。这时，CPU 的缓存控制器**不看“页”，只看“行”**。它把物理内存中这个页里的数据，**只提取出需要的那个 64 字节（一行）**，搬运到 CPU 的 L1/L2/L3 缓存中供 CPU 运算。

#### "几路组相连"的含义

> 缓存被分为若干组(set), 一个地址通过**Index固定进某一组**;  "N 路"表示**每组有N个格子(way)**,  这个地址可以落在**其中任意一格,  查找时N路并行比较Tag**
>
> 另外 **Offset**:
>
> - CO(Cache Offset): 缓存行内偏移量, 决定了从一个**缓存行**(64B, 64字节)中取**哪一个字节**
> - VPO/PPO: 页内偏移量 : 决定了从一个**"页"**(4KB, 4k字节)中取出**哪一个缓存行(64字节)**
>
> 在组相连缓存中，一个内存地址会被CPU拆分成三个字段（从高位到低位）：**Tag（标记） | Index（组索引） | Offset（块内偏移）**。

<img src="./imgs/image-20260827145009355.png" alt="image-20260827145009355" style="zoom: 67%;" />

组数, Index位宽(位数), Offset位宽(位数) Tag位宽(位数) 三者之间的公式关系

- `组数 = 总行数 ÷ 路数`（如 24 行 ÷ 3 路 = 8 组 → CI 取 3 位, 这里的行在后面的示意图里表示一个长方形）
- `Index 位数 = log₂(组数)`
- `Offset 位数 = log₂(行大小)`
- `Tag 位数 = 地址总位宽 − Index − Offset`（TLB 里就是 `TLBT = VPN − TLBI`）

#### 核心模块区分

|              | **页表**         | **TLB**                | **Cache**          |
| :----------- | :--------------- | :--------------------- | :----------------- |
| **存什么**   | **VPN→PPN 映射** | **最近用过的 VPN→PPN** | **数据块本体**     |
| **在哪**     | 内存             | **CPU 内部**           | CPU 旁边(高速缓存) |
| **谁索引**   | VPN（下标）      | TLBI 索引 + TLBT 校验  | CI（PA 中位）      |
| **怎么命中** | 直接数组访问     | TLBT 组内比较          | CT 组内比较        |
| **未命中**   | 缺页 → 磁盘调页  | 查页表                 | 去内存取块         |
| **规模**     | 很大（256 项）   | 很小（16 项）          | 中（24 行）        |

#### 虚拟地址和物理地址拆分

> **总原则: ** 
>
> 1. 两种地址都有 N 和 O的区分: VPN和VPO, PPN和PPO, 其中PPO和VPO是完全相同的都不参与地址翻译, 都是用作块内偏移
> 2. 页表和TLB是和虚拟地址关联的, 也就是VA的VPN, 和物理地址无关
> 3. Cache 是和物理地址关联的, 也就是PA的PPN, 和虚拟地址无关

### 5.1.2 DRAM 芯片结构和访问
DRAM芯片相比SRAM, **访问时间更长, 成本更低**, 存储密度更高, 因此被广泛使用在**主内存**中.

#### DRAM结构
<img src="./imgs/img5_1.png">

如图, 一个`8M x 8`的RAM芯片, 共有8M个超单元, 每个超单元存储8位数据, 因此总容量是64Mb=8MB.

#### 访问DRAM
访问DRAM需要**行地址**和**列地址**, 访问时先提供行地址, 选中对应的行, 然后提供列地址, 选中对应的列, 最后就可以访问到对应的内存单元了.
1. **行激活**: 内存控制器(memory controller)向DRAM芯片提供行地址, DRAM将第i行所有的超单元拷贝到**行缓冲区(row buffer)**中
2. **列选择**: 控制器发送列地址, 从行缓冲区中精准选中对应的超单元, 进行读写操作
3. **输出**: 这个超单元的w位数据通过n引脚发送到CPU. 
<img src="./imgs/img5_2.png">

这样设计的好处是: **极大的减少了地址线的数量**, 是DRAM能够实现高容量的核心原因
<img src="./imgs/img5_3.png">

### 5.1.3 存储器模块
**存储器模块**(memory module)是由多个DRAM芯片组成的一个物理单元, 通过总线与CPU连接. 
**主存（通常也直接称为“内存”或“RAM”）** 是一个逻辑概念，它是计算机硬件架构中直接受 CPU 寻址并与之交换数据的核心存储空间。

#### 局部性原理
计算机程序具有**局部性(Locality)**, 这一点就能够**缓解CPU和内存之间的这执行速度差异**.

**局部性原理**: 一个**编写很好**的程序倾向于引用**最近引用过的数据本身**, 或者引用的数据项**邻近于其最近引用过**的数据项
局部性分为两种:
1. **时间局部性**: 被引用过的数据很可能很快会被再次引用
2. **空间局部性**: 一个存储位置被引用了一次, 很可能很快其附近存储位置就会被引用

#### 映射规则
**映射规则**的目的是**确定主存中的一个块(block)应该被放置在高速缓存的哪个位置**. 映射规则有三种:
1. **直接映射**(Direct Mapping): 每个主存块只能映射到高速缓存中的**一个特定位置**
2. **全相联映射**(Fully Associative Mapping): 每个主存块可以映射到高速缓存中的**任意位置**
3. **组相联映射**(Set Associative Mapping): Cache被分成若干组, 每个主存块只能映射到高速缓存中的一个**特定组**内的**任意位置**

三个映射规则各有优缺点, 主要考察他们的空间利用率和冲突概率

**根据E(每个组的高速缓存行数)**高速缓存被分为不同的分类
- 全相联高速缓存 -- 只有一个组
- 直接映射 -- 有多个组, 每个组只有一个行
- 组相联高速缓存 -- 有多个组, 每个组有多个行 [最正常]
